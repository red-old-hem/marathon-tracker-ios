# マラソン18週トレーナー

おかやまマラソン2026(2026年11月8日)に向けて作った、レース後も記録と次の目標を管理できる iOS トレーニングトラッカーです。

「意思が弱くても続く」ことを最優先に設計しています。記録の手間を極限まで減らし、完璧でなくても継続できる仕組みを入れてあります。

## 特徴

### 続けるための仕組み

- **ワンタップのチェックイン** — 走った日は1タップ。迷った日のための「5分だけ走った」ボタンを常設し、ゼロの日を作らないことを優先します
- **過去日の記録・編集** — カレンダーの日付をタップして、入力し忘れた日の追加や既存記録の修正ができます
- **次の目標設定** — 完走後はレース名、開催日、目標内容を設定できます。岡山マラソンの記録はそのまま残り、JSONバックアップにも含まれます
- **筋トレ記録と提案** — ランと同じ日にも残せます。エニタイムフィットネスで一般的なレッグプレス、チェストプレス、ラットプルダウンなどのマシン中心テンプレートから始め、種目ごとの重量・回数・セット、RPE、筋肉痛・張りを記録できます。ラン予定、痛み、直近の負荷から当日のメニューも提案します。店舗にない機器は適用後に種目名を編集できます
- **週2回の最低ライン** — 週3〜4回がベストでも「週2回できていれば達成」と定義。1回サボっても計画は崩れません
- **ヘルスケア自動チェックイン** — Apple Watch などのランニングワークアウトを読み取り、走った日を距離・時間つきで自動記録します。連携状態、最終同期時刻、同期結果やエラーも画面上で確認できます
- **通知** — 毎日20時に未チェックなら確認、火・木・土の朝7時にその日のメニューを通知します
- **JSONバックアップ** — 記録をファイルに書き出し、機種変更や再インストール後に読み込めます

### トレーニングと食事

- **18週間のプラン内蔵** — 基礎期 → 走り込み期 → 実戦期 → 調整期の4フェーズ。その日にやることだけを表示します
- **今日の食事** — フェーズと曜日、レースまでの日数から自動で切り替わります。レース3日前になると自動でカーボローディングの指示に変わります

### 故障の予防

- **痛みの記録** — チェックイン時に部位をワンタップで記録できます
- **連続検知と休養推奨** — 同じ部位の痛みが2回続くと注意、3回以上で強い警告を出し、朝の通知も休養推奨に切り替わります
- **「痛みで休んだ」を達成扱いに** — 警告中は休養も週2回の最低ラインにカウントします。「休むとストリークが途切れる」設計だと、痛くても走ってしまい逆効果になるためです

### 記録の可視化

- **週別の走行距離グラフ** — 18週分の実績(棒)と目標(破線)を並べて表示。横になぞると週ごとの距離とペースが出ます
- **ペース表示** — 距離と時間からペースを自動算出します。ただし目標ペースは参照値として併記するだけで、達成/未達の判定はしません(このプランのイージーランは意図的に遅いため、常に「未達」と表示するのは逆効果です)

## 動作環境

- iOS 17.0 以降
- Xcode 16 以降
- [XcodeGen](https://github.com/yonaskolb/XcodeGen)

## ビルド方法

`.xcodeproj` は `project.yml` から生成するためリポジトリに含まれていません。

```bash
brew install xcodegen
xcodegen generate
open MarathonTracker.xcodeproj
```

Xcode で Signing & Capabilities からご自身の Team を選択して実行してください。

無料の Apple ID で実機にインストールした場合、署名が7日で失効するため定期的な再インストールが必要です。

## テスト

テストターゲットも `project.yml` で管理しています。プロジェクトを再生成した後、シミュレータで実行します。

```bash
xcodegen generate
xcodebuild -project MarathonTracker.xcodeproj -scheme MarathonTracker \
  -destination 'platform=iOS Simulator,name=iPhone 15' test
```

## 設計上の注意点

コードを変更する際に壊しやすい不変条件があります。

1. **日付計算に `Calendar.current` を使わない** — 端末の暦法が和暦だとカウントダウンが壊れます。グレゴリオ暦固定の `Plan.calendar` を使ってください
2. **`RunLog` に追加するフィールドは必ず Optional にし、末尾に足す** — 合成 `Codable` は非Optional に `decode` を生成するため、デフォルト値があっても旧データの読み込みで throw します。`TrackerStore.init` は辞書全体を `try?` でデコードするので、1件の失敗が全記録の消失につながります。筋トレ専用モデルは新規作成されるデータなので、この制約の対象外です
3. **`km` は手入力専用** — ヘルスケア由来の距離は `autoKm` に持ち、表示は `distanceKm`(= `autoKm ?? km`)を使います。同じランの二重計上を防ぐためです
4. **ヘルスケア同期は種別を書き換えない** — 「5分だけ」「痛みで休んだ」を自動で「走った」に昇格させると、痛み警告が不当に解除されます。距離と時間だけを追加します

## 構成

| ファイル | 役割 |
|---|---|
| `Models.swift` | トレーニングプラン、食事ロジック、記録の保存と集計 |
| `ContentView.swift` | メイン画面の各カード |
| `DistanceChartCard.swift` | 週別走行距離グラフ(Swift Charts) |
| `HealthKitManager.swift` | ワークアウトの読み取り、自動チェックイン、同期状態の保持 |
| `NotificationManager.swift` | ローカル通知のスケジューリング |

記録は端末内の `UserDefaults` にのみ保存され、外部に送信されません。
